# Raider v1.1 구현 계획

이 문서는 실시간 라이브 스트리밍 레이더(Raider) 서비스의 사용성과 시각적 가치(Aesthetics)를 개선하기 위한 마이너 업데이트(v1.1) 설계 및 구현 계획을 보관합니다.

## Goal
- **새로고침 기능**: 사용자가 원할 때 즉시 전체 플랫폼 수집을 실행하고 화면을 갱신하는 새로고침 구현.
- **태그 정렬 수정**: 필터 영역의 태그 칩 수직 정렬 어긋남 해결.
- **검색 및 태그 UX 고도화 (삭제 및 추가)**:
  - **태그 토글 및 해제**: 이미 활성화된 태그를 다시 클릭하면 필터가 해제(삭제)되는 토글링 구현.
  - **활성 필터 칩 (Active Filter Chips)**: 검색 영역 하단에 현재 적용 중인 필터(`[플랫폼: 숲 ×]`, `[태그: 리그 오브 레전드 ×]`, `[검색어: 페이커 ×]`)를 개별 닫기(`×`) 버튼이 있는 칩으로 표시하여 쉽게 해제할 수 있도록 개선.
  - **태그 더 보기 (드로어)**: 숨겨진 인기 태그들을 확인할 수 있는 아코디언 드로어 구현 (최대 30개).
  - **카드 내 태그 클릭**: 방송 카드 내 태그 클릭 시 해당 태그 필터가 즉시 적용(추가)되도록 개선.
- **그리드 및 카드Legibility 개선**: 그리드 간격을 좁히고 카드 텍스트 크기와 마진을 최적화하여 가독성 및 시각 정보 밀도 상승.

## 1. 성공 조건 및 검증 방법
### 성공 조건
- 사용자가 새로고침 버튼을 누르면 백그라운드에서 즉시 수집이 돌고, 화면에 `갱신 중...` 스피너가 표시된 뒤 완료되면 자동 리로드되어 최신 데이터가 반영된다.
- 태그 필터 라인이 수직 중앙에 정렬된다.
- 활성화된 필터(태그, 플랫폼, 검색어)가 필터 제어 영역 하단에 `[필터명 ×]` 형태로 보이고, `×`를 누르거나 활성 태그를 다시 클릭하면 해당 필터가 즉시 해제된다.
- 카드 안의 태그를 누르면 해당 태그 필터가 검색 조건에 추가되어 화면이 필터링된다.
- 데스크톱/모바일 전체 화면에서 카드 정보(제목, 스트리머, 태그)가 더 밀도 있고 또렷하게 눈에 들어온다.

### 검증 방법
- `dotnet test` 실행 시 모든 단위/통합 테스트가 오류 없이 성공할 것.
- 빌드 경고 및 에러가 없을 것 (`dotnet build -warnaserror`).
- 브라우저 수동 검증: 실제 수집 유도 시 스피너 동작 및 페이지 자동 리프레시 검증, 레이아웃 정렬 및 글자 폰트 가독성 확인.

## 3. 결정 기록 (Decision Records)
- **비동기 갱신**: 사용자 요청 스레드에서 직접 API 수집을 대기(동기적 블로킹)하지 않고, 백그라운드 스레드에서 수집이 돌도록 트리거하고 웹 요청은 즉시 홈 화면으로 돌려보낸 후 JS 폴링으로 갱신을 감지함. 이 구조는 Raider의 코어 원칙인 "화면 요청 시 잠금이나 외부 I/O를 대기하지 않는다"를 유지함.
- **순수 CSS/HTML 아코디언/Vanilla JS**: 대형 UI 라이브러리를 추가하지 않는 원칙에 따라 태그 아코디언은 CSS 클래스 토글과 최소한의 Vanilla JS 스크립트만으로 가볍게 처리함.
- **태그 개수 표기 제외**: 플랫폼별 수집 주기(10분)의 시간 차와 스냅샷 데이터의 단순성을 유지하기 위해 복잡한 태그별 카운트 계산과 렌더링은 적용하지 않고, 정규화된 태그명의 필터링 및 토글 기능에만 집중함.
