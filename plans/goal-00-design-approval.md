# Goal 0. 다크 모드 화면 디자인 승인.

## 목표.

구현 전에 Raider의 다크 모드 전용 디자인 계약을 확정해 화면 구현 중 임의적인 색상, 폰트, 간격, 타일 구조 변경을 방지한다.

## 선행 조건.

- 제품의 필수 화면 정보가 확정되어야 한다.
- 타일 필수 정보는 플랫폼, 방송인 이름, 시청자 수, 제목, 썸네일, 원본 링크이며 태그는 최대 3개까지 보조 정보로 표시한다.

## 산출물.

- 루트 [DESIGN.md](../DESIGN.md).
- 검토 가능한 정적 HTML/CSS 프로토타입.
- 승인된 색상, 타이포그래피, 간격, 타일, 반응형, 상태, 접근성 계약.
- Goal 6 시각 검증 체크리스트.

## Task.

### Task 0.1. 시각 방향을 승인한다.

- [x] 다크 모드 전용으로 확정한다.
- [x] Raider 중립 브랜드 색상과 플랫폼 보조 색상을 정한다.
- [x] 외부 폰트 CDN 없이 시스템 폰트 스택을 사용한다.
- [x] 사용자가 전체 시각 방향을 승인한다.

### Task 0.2. 라이브 타일 계약을 승인한다.

- [x] 16:9 썸네일 중심 타일 구조를 정한다.
- [x] 플랫폼 뱃지와 시청자 수 오버레이 위치를 정한다.
- [x] 제목 두 줄과 방송인 이름 한 줄 규칙을 정한다.
- [x] 타일 전체 클릭 시 원본 방송으로 이동하도록 정한다.
- [x] 사용자가 타일 정보 우선순위와 밀도를 승인한다.

### Task 0.3. 반응형과 상태 화면을 승인한다.

- [x] 데스크톱과 모바일 열 수 목표를 정한다.
- [x] 첫 수집, 빈 목록, 부분 장애, 초기 실패 화면 규칙을 정한다.
- [x] 접근성과 성능 디자인 규칙을 정한다.
- [x] 사용자가 모바일과 상태 화면 방향을 승인한다.

### Task 0.4. 정적 디자인 프로토타입을 검증한다.

- [x] `prototype/`에 정적 HTML/CSS 프로토타입을 만든다.
- [x] 데스크톱 1280px 화면을 시각 검수한다.
- [x] 모바일 375px 화면을 시각 검수한다.
- [x] 플랫폼 필터, 태그 필터, 태그 검색 동작을 검증한다.
- [x] 태그 표시, 태그 필터, 태그 검색 디자인 계약을 승인한다.
- [x] 사용자가 실제 프로토타입 화면을 승인한다.

## 검증 방식.

이 Goal은 코드 TDD 이전의 디자인 계약 단계다. 구현 후 검증 가능한 요구사항으로 표현됐는지 확인한다.

- 색상과 크기는 CSS token으로 구현 가능해야 한다.
- 반응형 규칙은 Playwright viewport 테스트로 검증 가능해야 한다.
- 타일 필수 정보와 링크는 HTML 계약 테스트로 검증 가능해야 한다.
- 상태 화면은 fixture 기반 E2E 테스트로 검증 가능해야 한다.
- 접근성 요구는 자동 검사와 키보드 탐색으로 검증 가능해야 한다.

## 완료 조건.

- 사용자가 `DESIGN.md`의 전체 방향을 승인한다.
- 미확정 디자인 결정이 남지 않는다.
- Goal 6의 모든 UI Task가 `DESIGN.md`를 기준으로 테스트 가능하다.
