# Goal 6. 검색 가능한 라이브 타일 화면 완성.

## 목표.

현재 메모리 스냅샷을 Razor Pages로 빠르게 렌더링하고 플랫폼, 태그, 검색어로 방송을 쉽게 탐색하게 한다.

## 산출물.

- Razor Pages 홈 화면과 타일 partial.
- 반응형 CSS 디자인 시스템.
- 플랫폼, 태그, 방송인 이름, 제목 검색.
- 상태 화면과 Playwright 시각 검증.

## Task.

### Task 6.1. 타일 HTML 계약을 만든다.

- [x] 플랫폼, 방송인 이름, 시청자 수, 제목, 썸네일, 최대 3개 태그 표시 테스트를 작성한다.
- [x] 전체 타일 링크, 대체 텍스트, 지연 로딩, 기본 썸네일 테스트를 작성한다.
- [x] Razor partial과 안전한 외부 링크를 구현한다.

### Task 6.2. 홈 화면과 필터를 만든다.

- [x] 시청자 수 정렬, 플랫폼 필터, 태그 필터, 방송인·제목·태그 검색 조합 테스트를 작성한다.
- [x] query parameter가 새로고침과 공유 후 유지되는 테스트를 작성한다.
- [x] 스냅샷을 한 번 읽는 Razor Page를 구현한다.

### Task 6.3. 상태 화면을 만든다.

- [x] 첫 수집, 빈 목록, 일부 플랫폼 장애, 오래된 목록 테스트를 작성한다.
- [x] 스켈레톤과 안전한 상태 안내를 구현한다.

### Task 6.4. 반응형 시각 디자인을 완성한다.

- [x] `DESIGN.md` 토큰, 그리드, 타일, 태그 칩, 필터 줄바꿈, 접근성을 구현한다.
- [x] Playwright로 데스크톱과 모바일을 시각 검수한다.

### Task 6.5. 화면과 검색 성능을 검증한다.

- [x] 대표 방송 및 태그 fixture로 검색 결과와 홈 화면 p95를 측정한다.
- [x] 수집 중 화면 응답 시간을 측정한다.
- [x] 불필요한 원본 JSON과 대형 JavaScript가 HTML에 없는지 확인한다.

## 검증 결과.

- 500개 대표 방송의 필터된 홈 화면 자동 테스트 p95는 `24.901ms`였고 HTML은 약 `95KB`였다.
- 실제 두 플랫폼 수집 결과 5,738개에서 페이지당 120개를 렌더링했으며 홈 화면 HTML은 약 `133KB`, p95는 `40.28ms`였다.
- 수집과 readiness 전환 중 홈 요청 25회의 p95는 `99.6ms`였다. 최초 Razor 컴파일 요청 최대값은 `1,748.41ms`였다.
- 1440×900에서 4열, 375×812에서 1열과 가로 스크롤 없음, 조합 필터와 2페이지 query 유지, 깨진 이미지 0개, 브라우저 콘솔 오류 0개를 Playwright로 확인했다.
- 화면은 JavaScript를 포함하지 않고 단일 CSS만 사용하며 원본 JSON을 HTML에 포함하지 않는다.

## 검증 명령.

```text
dotnet test --filter Web
dotnet test
playwright test
```

`HomePagePlaywrightTests`는 실제 Kestrel과 Chromium으로 데스크톱 검색, 모바일 375px 1열, 가로 스크롤 없음을 자동 검증한다. 추가로 Codex 인앱 Browser의 Playwright API로 실제 수집 데이터의 데스크톱과 모바일 화면을 시각 검수했다.

## 완료 조건.

- 플랫폼, 태그, 검색어 조합이 빠르고 예측 가능하게 동작한다.
- UI가 `DESIGN.md`와 접근성 계약을 준수한다.
- 한 플랫폼 장애 중에도 정상 방송을 탐색할 수 있다.
- 홈 화면 p95 100ms 미만 목표를 측정하고 기록한다.
