# Raider v1.2.0 공용 즐겨찾기 계획.

## Goal.

개인 Raider 서버에 접속하는 모든 컴퓨터가 하나의 방송인 즐겨찾기 목록을 공유하고, 홈 화면 왼쪽의 접이식 사이드바에서 즐겨찾기 방송인의 이름과 현재 라이브 여부를 빠르게 확인한다.

## 성공 조건.

- 현재 라이브 타일에서 방송인을 즐겨찾기에 추가하거나 제거할 수 있다.
- 즐겨찾기는 `(Platform, ChannelId)`로 식별하며 같은 채널이 중복 저장되지 않는다.
- 컨테이너 재시작, 재생성, 이미지 업데이트 뒤에도 서버 호스트 저장소의 즐겨찾기가 유지된다.
- 다른 컴퓨터에서 같은 Raider 서버에 접속하면 같은 즐겨찾기 목록을 본다.
- 즐겨찾기 방송인이 현재 스냅샷에 있으면 라이브로 표시하고 원본 방송으로 이동할 수 있다.
- 즐겨찾기 방송인이 오프라인이어도 마지막으로 확인한 방송인 이름을 표시한다.
- 데스크톱 사이드바는 접고 펼칠 수 있고, 모바일에서는 본문을 가리지 않는 드로어로 동작한다.
- 즐겨찾기 저장소 장애가 라이브 수집과 기본 홈 화면을 중단시키지 않는다.

## 범위 밖.

- 사용자 계정, 로그인, 사용자별 즐겨찾기.
- Raider 내부 인증과 권한 관리.
- 플랫폼의 오프라인 채널 API 호출.
- 과거 방송, 시청 기록, 알림, 즐겨찾기 그룹과 메모.
- 다중 Raider 인스턴스와 공유 네트워크 데이터베이스.

## 핵심 결정.

### 공용 저장소.

- 단일 Raider 인스턴스에 맞춰 SQLite 파일 하나를 사용한다. SQLite는 컨테이너 내부 영구 저장소가 아니라 서버 호스트에 저장된 파일을 읽고 쓰는 DB 엔진이다.
- SQLite 접근은 `Microsoft.Data.Sqlite`를 직접 사용한다. Entity Framework Core와 Repository 계층은 도입하지 않는다.
- 기본 컨테이너 경로는 `/data/raider.db`이며 서버 호스트의 명시적인 데이터 디렉터리를 `/data`에 bind mount한다.
- 기본 서버 경로는 Compose 파일 기준 `./data`로 두고 운영자가 `RAIDER_DATA_PATH`로 절대 경로를 지정할 수 있게 한다.
- Docker가 실제 위치를 숨기는 named volume보다 운영자가 직접 확인·백업·복구할 수 있는 bind mount를 사용한다.
- 데이터베이스 디렉터리만 쓰기 가능하게 하고 컨테이너의 나머지 루트 파일시스템은 읽기 전용으로 유지한다.
- 애플리케이션 시작 시 존재하지 않는 테이블과 인덱스를 멱등적으로 생성한다.
- 초기화 실패는 애플리케이션 시작과 라이브 수집을 막지 않는다. 즐겨찾기 API와 사이드바만 안전한 장애 상태를 반환한다.
- 연결은 작업마다 짧게 열고 닫으며 busy timeout과 제한된 재시도를 적용한다.

### 데이터 모델.

`favorites` 테이블.

| 열 | 의미 |
| --- | --- |
| `platform` | `chzzk` 또는 `soop`. |
| `channel_id` | 현재 스냅샷에서 확인한 플랫폼 내 canonical 채널 식별자. |
| `streamer_name` | 오프라인 표시를 위한 마지막 확인 이름. |
| `created_at_utc` | 최초 즐겨찾기 추가 시각. |
| `updated_at_utc` | 이름 등 저장 정보의 마지막 갱신 시각. |

- 기본 키는 `(platform, channel_id)`다.
- `BroadcastId`는 방송마다 바뀔 수 있으므로 즐겨찾기 식별자로 사용하지 않는다.
- 라이브 여부, 방송 제목, 시청자 수, 썸네일, 방송 URL은 DB에 저장하지 않고 현재 메모리 스냅샷에서 가져온다.
- v1.2.0에서는 즐겨찾기 추가 시 현재 스냅샷에서 확인한 이름만 저장한다. 자동 이름 갱신은 수집 경로의 DB 쓰기를 피하기 위해 범위 밖으로 둔다.

### 라이브 상태.

- 즐겨찾기 목록 조회 시 DB 레코드와 `SnapshotStore.Current.Live.Streams`를 `(Platform, ChannelId)`로 결합한다.
- 라이브 항목은 먼저, 오프라인 항목은 다음에 표시한다.
- 각 그룹 안에서는 방송인 이름을 대소문자 무시 오름차순으로 정렬한다.
- 플랫폼의 마지막 성공 목록이 최신이면 `라이브` 또는 `오프라인`으로 표시한다.
- 플랫폼 수집이 실패했거나 오래된 상태이면 해당 플랫폼의 즐겨찾기는 `상태 확인 지연`으로 표시하고 마지막 목록만 보조 정보로 사용한다.
- 화면 요청 중 외부 플랫폼 API를 호출하지 않는다.

### HTTP 경계.

- `GET /api/favorites`: 현재 즐겨찾기와 라이브 상태를 반환한다.
- `PUT /api/favorites/{platform}/{channelId}`: 서버가 현재 스냅샷에서 canonical 채널 ID와 방송인 이름을 확인한 뒤 추가한다.
- `DELETE /api/favorites/{platform}/{channelId}`: 즐겨찾기를 제거한다.
- 현재 스냅샷에 없는 채널을 PUT으로 임의 추가할 수 없다.
- 쓰기 요청은 동일 출처 정책과 antiforgery 보호를 적용하며, 외부 공개 시 reverse proxy 인증과 직접 포트 접근 차단을 운영 전제조건으로 둔다.
- 입력 플랫폼과 채널 ID의 길이·허용값을 검증하고 스냅샷의 canonical 값을 저장한다.
- SQL 파라미터를 사용하고 원본 사용자 입력을 로그에 기록하지 않는다.

### UI.

- 데스크톱에서는 상단 바 아래 왼쪽에 고정 폭 즐겨찾기 사이드바를 둔다.
- 사이드바는 접었을 때 좁은 레일과 펼치기 버튼만 유지한다.
- 펼침 상태는 브라우저별 표현 상태이므로 `localStorage`에 저장한다.
- 모바일에서는 기본 닫힘 드로어와 명시적인 열기/닫기 버튼을 사용한다.
- 모바일 드로어는 `aria-expanded`, Escape 닫기, 포커스 복귀, 배경 상호작용 차단과 스크롤 잠금을 지원한다.
- 사이드바는 라이브 방송인을 위에 표시하고 라이브 상태 텍스트와 점을 함께 제공한다.
- 라이브 즐겨찾기 선택 시 현재 `WatchUrl`을 새 탭에서 연다.
- 오프라인 즐겨찾기는 비활성 상태로 표시하며 이름과 플랫폼, `오프라인` 상태를 유지한다.
- 각 라이브 타일에는 별도 즐겨찾기 토글 버튼을 둔다. 현재 타일 전체가 링크이므로 유효하지 않은 중첩 인터랙션이 생기지 않게 타일 DOM 구조를 조정한다.
- API 실패 시 토글 상태를 낙관적으로 확정하지 않고 짧은 안전한 오류 상태를 표시한다.

## Grill 결과.

### Blocking questions.

- 없음. 개인 서버의 모든 접속자가 하나의 공용 즐겨찾기 목록을 사용한다는 전제로 구현할 수 있다.

### Non-blocking concerns.

- 인증 없이 외부에 공개하면 접속 가능한 누구나 즐겨찾기를 변경할 수 있다.
- SQLite bind mount는 기존 무볼륨 운영 계약을 변경하므로 서버 경로 권한과 백업·복구 절차가 필수다.
- 현재 스냅샷에 없는 오프라인 채널의 이름 외 상세 정보는 알 수 없다.
- 플랫폼 수집 실패나 오래된 스냅샷에서는 라이브 여부를 확정할 수 없다.

### Scope pressure.

- 작은 옵션: 첫 릴리스에는 공용 즐겨찾기, 라이브 여부, 사이드바만 제공한다.
- 피할 것: 사용자별 목록, 알림, 오프라인 플랫폼 API, 그룹, 메모, 범용 저장소 추상화.

### Verification pressure.

- 최소 검증: SQLite 재개방·병렬 CRUD·장애 격리, API CRUD와 위조 입력 거부, 현재 스냅샷 라이브 결합, Playwright 사이드바 흐름.
- 회귀 검증: 기존 검색·필터·새로고침·반응형·컨테이너 읽기 전용 계약.

### Recommendation.

공용 SQLite와 스냅샷 결합 방식으로 v1.2.0을 진행한다.
