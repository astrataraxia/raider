# v2.4.0 UI 업데이트 계획

화면과 버전 번호는 브랜치 `v2.4.0-ui`에 반영했다. 배포는 하지 않았다.

기준 화면은 `prototype/ui-mockup-2.4.html`이다. 현재 앱은 홈(`/`), 리캡(`/recap`), 상태(`/status`)가 이미 있고 데이터도 있다. 2.4.0은 그 화면을 목업의 코랄 다크 레이아웃으로 맞추고, 홈에 즐겨찾기 라이브 피처드만 새로 넣는다.

## 목표

- 세 페이지가 목업과 같은 헤더, 표면, 카드 구조를 쓴다.
- 검색, 플랫폼·태그·즐겨찾기·카테고리 필터, 페이지, 새로고침, 즐겨찾기 추가·삭제·카테고리 이동, 사이드바 접기, 모바일 즐겨찾기 서랍, 리캡 로그인·로그아웃, 상태 수치가 지금과 같이 동작한다.
- 구현이 끝나면 브라우저에서 그 동작을 누르고, 목업과 실제 화면을 같은 크기로 찍어 `images/v2.4-ui/`에 남긴다.

## 범위

한다.

- `site.css` 색과 레이아웃을 목업 토큰으로 바꾼다. 배경 `#101114`, 강조 `#dc887e`, 라이브 `#ff5572`, CHZZK `#00e56b`, SOOP `#4b9dff`. 보라 `#8b7cff` 헤더는 빼는 대상이다.
- 헤더를 가운데 알약 내비게이션으로 바꾼다. 링크는 `라이브` `/`, `리캡` `/recap`, `상태` `/status`이고 현재 페이지에 `aria-current="page"`를 둔다. 목업의 한 페이지 탭 전환은 쓰지 않는다.
- 홈 상단에 `TODAY'S PICK` 피처드 카드를 둔다. 대상은 현재 스냅샷에서 라이브인 즐겨찾기다. 페이지에 잘린 120개 목록이 아니다.
- 리캡과 상태를 목업의 유리 카드, 표, 월 막대, 서비스 카드로 다시 그린다. 숫자의 의미와 배지 규칙은 유지한다.
- 공통으로 보이는 헤더 마크업은 partial 하나로 모은다. 페이지마다 다른 조각(방송 수, 새로고침, 로그아웃)은 partial 인자로 남긴다.

안 한다.

- 수집, SQLite 스키마, 채팅 워커, `/health/live`, `/health/ready`, 즐겨찾기 API 계약을 바꾸지 않는다.
- 목업의 가짜 이모지 아바타, 샘플 이름, 샘플 수치를 넣지 않는다. 썸네일은 기존 `ThumbnailUrl`을 쓰고, 없으면 지금 placeholder를 쓴다.
- 즐겨찾기 사이드바를 모바일에서 없애지 않는다. 목업은 760px 아래에서 사이드바를 숨기지만, 지금 화면은 `즐겨찾기 열기` 서랍이 그 역할을 하고 Playwright가 그 열기·닫기를 잠근다. 서랍의 겉모양만 새 사이드바를 따른다.
- 헤더의 `N개 방송 중`과 히어로의 `검색 결과`는 필터가 적용된 개수다. 목업 문구 `전체 방송`으로 바꾸지 않는다. 필터를 켜도 전체 개수처럼 보이면 거짓이 된다.
- 피처드를 새로고침마다 다시 뽑지 않는다. 목업 문구는 "랜덤"이지만 스크립트도 클릭할 때만 넘긴다. 첫 카드는 시청자가 가장 많은 즐겨찾기 라이브다. 문구는 `시청자가 가장 많은 즐겨찾기 라이브`로 둔다.

## 피처드 동작

데이터는 서버에서 즐겨찾기와 현재 스냅샷의 교집합으로 만든다. 라이브가 아니면 빠진다. 카드에 필요한 제목, 태그, 썸네일, 플랫폼, 카테고리, 시청자 수, 시청 URL은 지금 즐겨찾기 API의 `FavoriteView`에 없다. 홈 모델에만 피처드 목록을 두고, 즐겨찾기 목록 API 응답은 그대로 둔다.

- 라이브 즐겨찾기가 없으면 피처드 구역과 `다른 즐겨찾기 라이브` 줄을 렌더하지 않는다. 그 아래 히어로, 필터, 그리드는 그대로다.
- 이전, 다음, 점, 다른 라이브 버튼, 사이드바의 라이브 행은 같은 목록 안에서 카드를 바꾼다. 사이드바의 오프라인 행은 지금처럼 시청 링크가 없고 피처드를 바꾸지 않는다.
- `바로 보기`는 그 방송의 `WatchUrl`을 새 탭으로 연다.
- `다른 즐겨찾기 라이브`는 현재 카드를 뺀 최대 3개다. 더 있으면 이전·다음과 점으로 간다.
- `refresh.js`가 `.sync-state`와 라이브 영역을 바꿀 때, 보고 있던 플랫폼+채널이 아직 라이브면 그 카드를 유지한다. 없어졌으면 시청자 수 1위 카드로 옮긴다.

## 리캡과 상태

리캡에 이미 있는 본진 비중, 총 채팅, 활동 채널, 활동 일수, 개근·고인물·일편단심·메뚜기, 최장·현재 연속 출석, 채널 목록, 월별 건수를 목업 배치로 보여 준다.

- 채널 표에 비중 열을 더한다. 값은 그 채널 건수 / 총 채팅이다.
- 월 막대는 있는 달만, 최근 6개월까지 그린다. 이번 달과 지난 달이 둘 다 있으면 증감 한 줄을 낸다. 달이 하나면 증감 문장은 내지 않는다.
- 이번 주 7칸은 본진 방송이 있던 최근 7일을 칠한다. 그 날 채팅이 있으면 채운 칸, 방송은 있었는데 채팅이 없으면 빈 칸이다. 휴방은 칸에 넣지 않는다. 이 배열은 `ViewerRecap`에 표시용으로만 더하고, 배지와 연속 출석 계산은 그대로 둔다.
- 로그인 전 안내, 로그인 실패 문구, 수집 시작 전 문구, 로그아웃 버튼은 유지한다.

상태는 프로세스 가동, 메모리, 메모리 한도, CHZZK·SOOP 수집, 채팅 집계, 저장소, 최근 경고를 목업 카드로 다시 배치한다. 한도가 없으면 그 칸은 지금처럼 빠진다. 경고가 있으면 플랫폼, 작업, 오류 종류, 시각을 목록으로 보여 준다. 경고가 없으면 목업의 빈 상태 문구를 쓴다. `/status`가 읽는 저장소와 health 경로는 바꾸지 않는다.

## 유지할 연결점

JS와 테스트가 이미 잡는 이름을 바꾸지 않는다.

- `.sync-state`, `[data-refresh-form]`, `[data-live-content]`
- `#favorites-sidebar`, `.favorites-sidebar`, `.favorites-collapse`, `.favorites-mobile-toggle`, `.favorites-backdrop`, `.is-mobile-open`
- `.favorite-item`, `.favorite-toggle`, `.stream-card`와 카드의 `data-broadcast-id`, `data-platform`, `data-channel-id`
- 즐겨찾기 드래그로 카테고리를 옮기는 동작, 카테고리 추가 버튼

태그 더 보기, 적용된 필터 칩, 카테고리 필터, 페이지네이션, 수집 지연·설정 오류·빈 목록·첫 수집 골격은 필터 카드 아래와 그리드 자리에 남긴다. 목업에 없다고 빼지 않는다.

## 자바스크립트

지금은 `wwwroot/js/favorites.js`와 `refresh.js` 두 파일이 각각 즉시 실행 함수이고, 선언은 `var`다. 홈의 태그 서랍은 `Index.cshtml` 안의 인라인 스크립트다. 새로고침이 즐겨찾기를 다시 그릴 때는 `window.RaiderFavorites`로 건너간다. 같은 `localStorage` JSON 읽기가 `favorites.js` 안에 세 번 있다.

동작은 유지하고 파일만 나눈다. 번들러와 새 패키지는 넣지 않는다. v2.1.0에서 미룬 대로 즐겨찾기 DOM을 `<template>`로 다시 짜지 않는다.

파일:

- `storage.js`: `localStorage` JSON 읽기·쓰기. 커스텀 카테고리, 카테고리 순서, 접힌 카테고리, 사이드바 접힘, 태그 서랍이 이 함수를 쓴다.
- `favorites-api.js`: antiforgery 토큰, 목록 조회, 토글, 카테고리 변경.
- `favorites-sidebar.js`: 접기, 모바일 서랍, 뷰포트.
- `favorites-list.js`: 카테고리 렌더, 드래그 이동, 카테고리 추가. 헤더와 그룹에 반복된 드롭 바인딩은 한 함수로 둔다.
- `refresh.js`: 부분 HTML 교체와 수집 폴링.
- `tags.js`: 지금 인라인인 태그 서랍.
- `featured.js`: 피처드 카드. 라이브 영역이 교체된 뒤 보고 있던 방송을 다시 고른다.
- `home.js`: 위 모듈을 불러 시작한다.

페이지에는 스크립트 파일만 연결한다.

```html
<script type="module" src="/js/home.js" asp-append-version="true"></script>
```

`type="module"`이 로딩 옵션이다. 모듈 스크립트는 기본이 defer라 파싱을 막지 않고, 문서가 파싱된 뒤에 의존 순서대로 실행된다. `async`는 쓰지 않는다. 모듈에 `defer`를 또 붙이지 않는다. `DOMContentLoaded`로 태그 서랍을 한 번 더 감싸지 않는다. `Index.cshtml`의 인라인 스크립트는 지운다. 리캡과 상태는 이 스크립트를 넣지 않는다.

`import`한 파일에는 `asp-append-version`이 따라가지 않는다. 홈에서 `IFileVersionProvider`로 import map을 만들어 `#storage`, `#favorites-api` 같은 각 URL에 지금 태그 헬퍼와 같은 내용 지문을 붙인다. `home.js`는 그 이름을 import한다. 전역 `window.RaiderFavorites`는 없앤다. `refresh.js`는 같은 모듈 그래프의 `refresh`를 호출한다.

`wwwroot/js` 안에 `var`를 남기지 않는다. 다시 할당하면 `let`, 아니면 `const`다.

사이드바, 목록, 접기 버튼, 모바일 토글, 배경, 페이지, 헤더, 토큰 중 하나라도 없으면 즐겨찾기 시작은 지금처럼 바로 반환한다. 셀렉터 이름은 유지할 연결점과 같다.

## 검증

자동:

- `dotnet test`
- `dotnet format --verify-no-changes`
- `dotnet build --no-restore -warnaserror`

브라우저에서 로컬 앱을 띄우고 Brave(`agent-browser`, `/usr/bin/brave`)로 누른다. 스크린샷 한 장으로 끝내지 않는다.

홈, 데스크톱과 390px:

- 검색어를 넣고 검색하면 그 방송만 남고 URL에 `q`가 있다.
- CHZZK, SOOP, 즐겨찾기, 태그, 카테고리, 칩 해제, 초기화가 목록을 바꾼다.
- 새로고침 컨트롤이 수집 중 표시로 바뀌고, 끝난 뒤 스냅샷 시각이 갱신된다.
- 카드의 즐겨찾기 토글이 사이드바에 반영된다. 카테고리 추가와 드래그 이동이 된다.
- 사이드바 접기가 동작한다. 390px에서는 `즐겨찾기 열기`로 서랍이 열리고 배경을 누르면 닫힌다. 가로 스크롤이 생기지 않는다.
- 즐겨찾기 라이브가 둘 이상일 때 이전, 다음, 점, 다른 라이브, 사이드바 라이브 행이 같은 카드의 제목·시청자·`바로 보기` URL을 바꾼다. 라이브가 없으면 피처드가 없다.
- 태그 더 보기가 새로고침 뒤에도 열림 상태를 유지한다.
- 홈의 스크립트는 `type="module"` 하나다. 페이지 안에 인라인 스크립트가 없고, `wwwroot/js`에 `var`가 없다.

리캡:

- 로그아웃 상태에서는 치지직 로그인 링크가 있다.
- 로그인 상태에서는 본진 이름, 비중, 총 채팅, 채널 표, 월 막대가 저장값과 같다. 로그아웃이 된다.

상태:

- 가동, 메모리, 두 플랫폼, 채팅, 저장소가 보인다.
- 경고가 없으면 빈 상태가, 있으면 경고 행이 보인다.
- `/health/live`와 `/health/ready` 응답은 이 변경 전과 같다.

목업 비교:

- `prototype/ui-mockup-2.4.html`과 실제 `/`, `/recap`, `/status`를 1440×900과 390×844에서 찍는다.
- 파일은 `images/v2.4-ui/`에 `mockup-live-desktop.png`, `app-live-desktop.png`처럼 목업과 앱을 짝으로 둔다. 채팅에서 프로젝트 경로로 열 수 있게 저장소 안에 둔다.
- 이 문서 끝의 비교 메모에 짝 경로와, 의도적으로 다른 점을 적는다. 다른 점은 실제 썸네일과 이름, 새로고침, 로그아웃, 필터 칩, 모바일 즐겨찾기 버튼, 피처드 문구가 `시청자가 가장 많은 즐겨찾기 라이브`인 것이다.
- 헤더 알약, 사이드바, 피처드 좌우 분할, 3열 그리드, 리캡 본진 카드와 두 열, 상태 3요약과 2열 서비스 카드가 목업과 같은 구역에 있는지를 본다. 픽셀이 같지 않은 것은 실패로 보지 않는다. 구역이 빠지거나 모바일에서 겹치면 실패다.

의도적으로 다른 점은 다음과 같다.

- 앱은 실제 썸네일과 방송 이름을 쓴다. 목업의 이모지 아바타와 샘플 이름은 없다.
- 피처드 문구는 `시청자가 가장 많은 즐겨찾기 라이브`다.
- 헤더의 방송 수는 필터가 적용된 개수다. `전체 방송`으로 바꾸지 않는다.
- 새로고침, 로그아웃, 필터 칩, 모바일 `즐겨찾기 열기`는 앱에만 있다. 목업은 760px 아래에서 사이드바를 숨긴다.
- 리캡 앱 캡처는 로그아웃 상태다. 목업은 샘플 통계다.
- 상태 앱에는 메모리 한도 칸이 없다. 이 실행에는 한도가 없다. 즐겨찾기 사이드바는 라이브에만 있고, 목업은 한 페이지라 상태에도 사이드바를 둔다.
- 상태 제목은 `서버 상태`다.

픽셀이 다른 것은 실패로 보지 않았다. 상태 요약 카드가 제목 아래가 아니라 아래로 밀려 있던 간격은 고친 뒤 다시 찍었다.
