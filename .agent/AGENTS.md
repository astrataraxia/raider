# Raider 저장소 작업 지침.

## 작업 시작.

- 작업 전에 `PLAN.md`, `ENGINEERING.md`, `DESIGN.md`를 읽는다.
- 현재 활성 계획이 있으면 해당 `plans/` 문서를 확인한다.
- 현재 `v1.3.10` 완료 범위와 검증 근거는 `RELEASES.md`를 확인한다.
- 구현 전에 성공 조건, 실패 조건, 검증 방법을 짧게 정의한다.
- 한 번에 하나의 Task만 진행한다. WIP 제한은 1이다.

## 제품 범위.

- CHZZK과 SOOP의 현재 라이브 방송만 수집한다.
- 다른 플랫폼, 과거 방송, 오프라인 채널, 시청 기록, 사용자 데이터는 범위 밖이다.
- 화면 요청은 외부 플랫폼을 호출하지 않고 현재 메모리 스냅샷만 읽는다.
- 방송 타일은 플랫폼, 방송인 이름, 시청자 수, 제목, 썸네일을 표시하고 원본 방송 페이지로 이동한다.
- 영구 데이터베이스와 영구 볼륨을 도입하지 않는다.

## 개발 방식.

- 모든 구현 Task는 Red, Green, Refactor, Verify 순서를 지킨다.
- 먼저 관찰 가능한 실패 테스트를 작성하고 의도한 이유로 실패하는지 확인한다.
- 테스트를 통과시키는 최소 구현만 작성한다.
- 테스트가 통과하는 상태에서만 리팩터링한다.
- 외부 API 호출은 자동 테스트에서 사용하지 않고 민감 정보가 제거된 fixture와 로컬 HTTP 테스트 서버를 사용한다.
- 아키텍처, 명명, 오류, 동시성, 설정, 보안 규칙은 `ENGINEERING.md`를 따른다.
- UI와 CSS 작업은 `DESIGN.md`를 따른다. 디자인 계약 변경은 구현보다 문서를 먼저 수정한다.
- 현재 Task에서 필요성이 증명되지 않은 추상화, 의존성, 설정을 추가하지 않는다.
- 코드는 단순하고 우아해야 한다. 우아함은 적은 개념, 명확한 이름, 짧은 실행 경로, 드러나는 데이터 흐름으로 판단한다.
- 같은 동작을 더 적은 타입, 계층, 분기, 설정으로 명확하게 표현할 수 있으면 단순한 쪽을 선택한다.

## 검증.

- 가장 작은 관련 테스트를 먼저 실행한 뒤 변경 위험에 맞춰 회귀 검증을 넓힌다.
- C# 코드 변경 시 최소한 다음 검사를 실행한다.

```text
dotnet test
dotnet format --verify-no-changes
dotnet build --no-restore -warnaserror
```

- 실제 외부 API 스모크 테스트는 반복 가능한 기본 테스트와 분리한다.
- 완료 전에 변경 범위, 관련 없는 수정, 누락 테스트, 비밀값 노출을 검토한다.

## 로컬 환경.

- Windows 로컬 개발은 .NET 10 SDK를 사용한다.
- 새 NuGet 패키지는 현재 Task에 필요성이 증명되고 .NET 및 ASP.NET Core 기본 기능으로 해결할 수 없을 때만 추가한다.
- Docker와 WSL은 컨테이너 작업을 시작하기 전까지 실행하거나 요구하지 않는다.
- 커버리지와 취약점 검사는 구현 기반이 준비된 뒤 CI에서 도입한다.

## 데이터와 비밀값.

- CHZZK 인증 정보와 기타 비밀값을 저장소 파일, fixture, 로그에 기록하지 않는다.
- 환경 변수는 `RAIDER_` 접두사를 사용한다.
- 실제 외부 응답을 fixture로 만들 때 최소 필드만 남기고 식별 정보와 비밀값을 제거한다.
- 외부 장애를 정상 빈 라이브 목록으로 처리하지 않는다.

## 계획 관리.

- 비범한 작업은 `plans/`에 활성 계획 문서 하나를 만들고 Task 체크리스트와 결정 기록을 갱신한다.
- Goal 범위나 제품 계약이 바뀌면 구현 전에 `PLAN.md` 또는 관련 계약 문서를 갱신한다.
- 완료된 계획은 핵심 결정과 검증 결과만 `RELEASES.md`에 압축하고 활성 계획 문서를 제거한다.
